# 架构

> 名称说明：本项目与 GitHub 上同名的 `agentbrowser/agentbrowser`（原 Synergy 分支，键鼠共享工具）无任何关系，不是其分支、衍生或重写。

## 一、为什么是这个形态

AI Agent 做网页任务，痛点在三个地方：登录态、启动参数、可观测性。

现有方案各有取舍：

| 方案 | 优点 | 对本场景的问题 |
|---|---|---|
| 每个技能自己起 Chrome | 简单 | 登录态 N 份；参数散落；出错无人知 |
| Playwright / Puppeteer | 能力强、生态好 | 需要 Node + 依赖；Agent 侧还要跑一套运行时 |
| 云浏览器（Browserbase / Steel） | 免运维、可并发 | 需要外网与账号；数据出本机 |
| MCP 浏览器服务 | 工具面统一 | 面向"模型调工具"，不解决登录态复用与任务可观测 |

AgentBrowser 的选择：**用本机 Chrome + 裸 CDP，一层薄管理**。

- Chrome 本身就是最完整的浏览器，CDP 是它自带的调试协议
- 管理只做四件事：分配实例与端口、维护 profile、写操作日志、发告警
- 不引入任何运行时依赖，Windows 上一个 .ps1 + 一个 .html 就够

## 二、分层

```
┌──────────────────────────────────────────────┐
│  Agent / 技能 / 定时任务                       │
│   └─ browser-pool.ps1 farm open <名字>             │
└───────────────┬──────────────────────────────┘
                │ 返回 http://127.0.0.1:<端口>
┌───────────────▼──────────────────────────────┐
│  AgentBrowser 引擎（PowerShell 5.1，单文件）        │
│  实例池  │  profile  │  日志  │  告警  │  面板  │
└───────────────┬──────────────────────────────┘
                │ Start-Process chrome --remote-debugging-port
┌───────────────▼──────────────────────────────┐
│  Chrome / Edge 实例（每实例独立 user-data-dir） │
│   └─ CDP: /json/list, WebSocket              │
└──────────────────────────────────────────────┘
```

关键约束：**端口即实例身份**。技能认端口，不认进程名；一个实例一个端口，互不干扰。

## 三、数据流：操作日志怎么来的

```
farm open
  └─ 起 Chrome（带 remote-debugging-port）
  └─ 确保面板在跑
  └─ 记录一条 activity（reused / 新起 / 达上限）

面板每 3 秒 GET /api/activity?act=drain
  └─ 对每个实例的每个标签页：
       ├─ 未埋点 → Page.addScriptToEvaluateOnNewDocument 注入 + Runtime.evaluate 立即装
       └─ Runtime.evaluate 取 window.__dfq 并清空
  └─ 写 logs\activity.jsonl（3MB 轮转，留 2000 行）
  └─ 返回按 task 分组的数据

页面侧埋点（捕获阶段监听，passive）
  copy / cut / paste / change(日期、文本) / focusin(日期框)
  click(按钮、下拉、复选框) / popstate / hashchange
  └─ 攒进 window.__dfq 数组（最多 400 条，防内存涨）

面板渲染
  └─ 一个 task = 一张卡；卡身固定 3 行高、超出滚动
```

为什么要"页面攒 + 面板拉"，而不是页面直接 HTTP 回写：页面发请求会被目标站的 CSP / 混合内容策略拦；由面板侧走 CDP 拉取最稳。

## 四、实例与任务的区分

| 概念 | 是什么 | 生命周期 |
|---|---|---|
| 实例（instance） | 一个 Chrome 进程 + 一个 profile + 一个端口 | 跨任务长期存在，登录态靠它 |
| 任务（task） | 一段工作的时间窗，面板上一张卡 | 30 分钟自动换段，或手动 `farm task` |

同一个实例上先后做三件事 = 三张卡（同一个浏览器，登录态不变）。

## 五、无头瘦身

空载实测（单页 about:blank）：

| 配置 | 内存 | 进程数 |
|---|---|---|
| 默认 headless | 约 650MB | 4 |
| headless + lean | 约 545MB | 2 |

lean 参数：`--disable-gpu --disable-software-rasterizer --renderer-process-limit=1`，并把 `CalculateNativeWinOcclusion` 加进 `--disable-features`。

有头实例不要开 lean（画面会掉帧）；有头的省内存只能靠少开标签页。

## 六、设计借鉴与来源声明

AgentBrowser 为独立实现。**未复制、未包含、未链接任何第三方源代码**；包内不存在第三方源码目录或第三方 LICENSE 文件。

设计思想的公开来源：

| 项目 | 许可证 | 借鉴的具体点 |
|---|---|---|
| [Playwright MCP](https://github.com/microsoft/playwright-mcp)（Microsoft） | Apache-2.0 | 持久化 profile、空闲超时回收、域名允许/阻止清单、以无障碍树/文本快照替代截图传给模型 |
| [Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp)（Chrome 团队） | Apache-2.0 | 以真实 Chrome 为后端；console 与网络请求的可观测性设计 |

上述许可证均为宽松许可，允许独立实现同类功能；本软件仅借鉴公开文档描述的设计思路与公开协议（Chrome DevTools Protocol 为公开规范），不构成对其代码的复制或衍生。

## 七、已知局限

- 仅 Windows（依赖 PowerShell 5.1 与 Windows 进程管理）
- 仅 Chromium 内核（Chrome / Edge）；Firefox 的 CDP 不完备
- 面板与调试端口无认证，仅适合单用户机器
- 埋点只挂主文档，跨域 iframe 内的操作记不到
- 无云端、无多机协同；所有数据在本机

# 例子：Agent 接一个需要登录的取数任务

场景：每周要去一个后台导一次报表，需要登录，导出后要落库。

## 0. 第一次：建实例、人工登录一次

```powershell
# 有头起来，让人扫码 / 输账号（不加 -Headful 默认是无头，无头没有窗口可扫）
powershell -File browser-pool.ps1 farm open 报表后台 https://example.com/login -Headful

# 登录完，把窗口挪到屏幕外（不抢焦点，但进程还在跑）
powershell -File browser-pool.ps1 farm park 报表后台
```

这一步只做一次。之后所有任务复用这个实例，**不用再登录**。

## 1. 每次任务：开任务段

```powershell
powershell -File browser-pool.ps1 farm task 报表后台 "周报取数 2026-W47"
```

面板上立刻出现一张新卡，标题就是任务名。

## 2. Agent 侧连 CDP

拿到 `farm open` 输出的端口（假设 9330，实际以命令输出为准，不要硬编码）。

**列页面（纯 HTTP，任何语言都行）**

```bash
curl -s http://127.0.0.1:9330/json/list
```

返回数组，每项有 `id`、`title`、`url`、`webSocketDebuggerUrl`。

**执行脚本（WebSocket）**

以下是 Node 18+ 的最小示例（`WebSocket` 已在全局；这只是示例代码，AgentBrowser 本身不依赖 Node）：

```js
const list = await (await fetch('http://127.0.0.1:9330/json/list')).json();
const page = list.find(p => p.type === 'page' && p.url.includes('example.com'));

const ws = new WebSocket(page.webSocketDebuggerUrl);
let id = 0;
const send = (method, params = {}) => new Promise(res => {
  const myId = ++id;
  const onMsg = e => {
    const m = JSON.parse(e.data);
    if (m.id === myId) { ws.removeEventListener('message', onMsg); res(m.result); }
  };
  ws.addEventListener('message', onMsg);
  ws.send(JSON.stringify({ id: myId, method, params }));
});

await new Promise(r => ws.addEventListener('open', r));

// 点一个按钮（selector 自己按页面结构调整）
await send('Runtime.evaluate', {
  expression: `document.querySelector('#export-btn').click()`,
  awaitPromise: true,
});

// 读页面上的数字
const r = await send('Runtime.evaluate', {
  expression: `document.querySelector('.total').innerText`,
  returnByValue: true,
});
console.log('合计:', r.result.value);

ws.close();
```

**提示**：`Runtime.evaluate` 是万能的，但别用它绕过页面本身的权限控制——它和人在页面上点是一样的身份。

## 3. 看它干了什么

打开 http://127.0.0.1:9410/ ，找到「周报取数 2026-W47」那张卡：

```

18:34:15  选日期 2026-11-11 ~ 2026-11-18
18:34:20  复制   合计 12,483.50
18:34:22  离开页面 example.com/export
```

日志区固定 3 行高，滚轮看全部。

## 4. 出错时告警

业务脚本里任何"要人介入"的分支都写一条：

```powershell
# 登录态失效
powershell -File browser-pool.ps1 farm alert 报表后台 warn "登录失效，需要人工扫码一次"

# 取数失败
powershell -File browser-pool.ps1 farm alert 报表后台 error "导出超时 3 次，本周数据未落库"
```

然后配一个定时任务扫 `logs\alerts.jsonl` 里 `pushed=false` 的条目，推到你的通知渠道（企业 IM、邮件、桌面通知都行），推完把 `pushed` 改成 `true`。

这样"任务失败"永远不会静默。

## 5. 收尾

```powershell
# 只关浏览器，登录态留着
powershell -File browser-pool.ps1 farm close 报表后台
```

不要删 `%USERPROFILE%\AgentBrowser`，删了就要重新登录。

---

## 常见变体

**多个账号**：每账号一个实例名（`账号A`、`账号B`），端口互不干扰，可并行。

**无人值守定时跑**：Windows 计划任务调你的取数脚本；脚本里先 `farm open`（幂等，已在跑就直接用），再干活，失败 `farm alert`。

**临时看看页面**：`farm open 临时 https://example.com` 用完 `farm close 临时`，profile 留着也没关系。

**完全隔离的测试环境**：

```powershell
$env:AGENTBROWSER_HOME = "$env:TEMP\df-test"
powershell -File browser-pool.ps1 farm open demo about:blank
```
